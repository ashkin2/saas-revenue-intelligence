# SaaS Revenue Intelligence - SQL + Python + Excel + Power BI + ML + LLM

An end-to-end analytics project for a B2B SaaS business: one warehouse, one set of KPI definitions, four delivery layers
(web dashboard, Excel executive report, Power BI model, Python ML) and an LLM layer that writes the executive narrative
under a numeric grounding check.

**Live dashboard:** open `dashboard/index.html` (no server, no build step, no external requests).

> **Data is synthetic** (1,800 customers, 24 months, generated by `data/generate_data.py`) so the project is fully
> reproducible and contains no confidential data. Figures demonstrate the method, not a real business.

## Business problem
Leadership asks four questions every month: *Is revenue growing for the right reasons? Are customers staying? Which
acquisition channels actually pay back? Who is about to churn and what is it worth?* This project answers them from one source of truth.

## Architecture
```
data/generate_data.py  ->  etl/etl_pipeline.py  ->  data/saas.db (star schema)
                                  |                       |
                                  |                  sql/kpi_queries.sql (7 KPI queries)
                                  v                       |
                      powerbi/data/*.csv        python/churn_model.py (ML + forecast)
                                  |                       |
                     Power BI (DAX measures)      ai/ai_insights.py (LLM + grounding check)
                                                          |
                    excel/build_report.py        dashboard/build_dashboard_data.py -> dashboard/index.html
```

| Layer | What it shows |
|---|---|
| **SQL** (`sql/`) | CTEs and window functions: MRR waterfall, NRR/GRR, unit economics, cohort retention, early-warning signals (LAG, NTILE), segment mix, MRR concentration |
| **Python ETL** (`etl/`) | Builds MRR movements (new / expansion / contraction / churn), loads a star schema, and **asserts the waterfall reconciles every month** (Ending = Start + New + Expansion - Contraction - Churn) |
| **Python ML** (`python/`) | 3-month churn classifier, time-based split, model chosen on a validation slice, permutation importance, calibration, risk tiers, expected MRR loss; damped-growth forecast with rolling-origin backtest |
| **Excel** (`excel/`) | 6-sheet executive workbook with live formulas, conditional formatting, charts and a scenario model (change churn / expansion / CAC inputs and the outputs recalculate) |
| **Power BI** (`powerbi/`) | Power Query loaders, 25+ DAX measures, theme, model and page layout guide |
| **AI** (`ai/`) | KPI context -> LLM -> structured insights -> **grounding check** that every number in the text exists in the source data |
| **Dashboard** (`dashboard/`) | 5 tabs, dependency-free SVG charts, light/dark theme, keyboard-accessible tabs |

## KPI definitions
MRR waterfall as above. NRR = (start MRR + expansion - contraction - churn) / start MRR. GRR excludes expansion.
Logo churn = churned customers / customers at start. LTV = ARPA / monthly logo churn. CAC = channel spend / new customers.
CAC payback = CAC / ARPA (months). Benchmarks used: LTV:CAC >= 3x, payback <= 12 months, NRR >= 100%.

## Run it
```bash
pip install -r requirements.txt
python data/generate_data.py
python etl/etl_pipeline.py
python python/churn_model.py
python dashboard/build_dashboard_data.py
python excel/build_report.py
# optional: python ai/ai_insights.py context | generate | verify
```
Then open `dashboard/index.html`. Re-running produces identical results (fixed seeds).

## The AI layer, honestly
- `ai_insights.py generate` calls the Anthropic API (set `ANTHROPIC_API_KEY`) with the KPI context and a strict system prompt.
- `verify` is a **guardrail**: every number in the generated text must match a source figure *in the right unit*
  (a $ amount cannot be "supported" by a coincidentally equal percentage). It is covered by negative tests with fabricated numbers.
- The `ai_insights.json` shipped here was written by Claude from `kpi_context.json` in a development session, then passed through
  the same check (71 figures, 0 unsupported). The live API path was not run in that session - run `generate` with your key to reproduce.

## Limitations (read before quoting numbers)
- Synthetic data: model metrics reflect the simulated churn process (engagement decay precedes churn), not real-world performance.
- Churn model signal is moderate (AUC 0.69); it is useful for ranking outreach, not for certainty. Gradient boosting did *not* beat the logistic baseline here, so the simpler model is shipped.
- The forecast interval comes from only 6 backtest origins and is likely optimistic.
- The DAX / Power Query files are written to the schema but **have not been executed in Power BI Desktop** - expect minor fixes on first load.
- No A/B test or holdout exists, so "recommended actions" are hypotheses with a stated success metric, not proven lifts.
